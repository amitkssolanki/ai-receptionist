# Phase 1 evidence (machine-readable)

Generated by the code in `app/services/evaluation/`, not typed in. Regenerate with:

```
RAILS_ENV=test bin/rails evidence:generate   # probe, latency, idempotency/cart versions, manifest
RAILS_ENV=test bin/rails evidence:suite      # runs the suite, replay and baseline:verify and records the counts
```

| File | What it is |
|---|---|
| `garlic_knots_probe.json` | 15 scenarios run through the real server path. Each separates what the assistant **claimed**, which tool calls the server **received**, which of them **mutated** the cart, and the resulting **authoritative order**. Prefixes are verbatim from real call #7. Like a live webhook, each tool call carries the scenario's own conversation so far, which the server's confirmation gate reads (`premature_submit_then_answered` shows the gate refusing the live premature-submit pattern). |
| `idempotency_and_versions.json` | Cart-version traces (before/after per tool call) and duplicate-delivery demonstrations: one execution, stored result returned, a late duplicate `get_cart` does not refresh the read-back. |
| `latency.json` | Server-side duration of each tool call (`ToolInvocation.duration_ms`) on the generating machine, with the Phase 0 sample for reference. Not Vapi round-trip latency. |
| `test_suite.json` | Counts from the full suite, the replay suite and `baseline:verify` at generation time. |
| `manifest.json` | Commit, versions, file hashes, and the list of live evidence that is **pending**. |

## What this evidence is not

- It is **not** a live model result. The scripted assistant behaviour is either recorded (call #7) or a deliberate
  variation; how often a live model makes a claim like this is the plan's Layer 3a sample (gpt-5-mini, N=20), which needs
  Vapi/OpenAI access and **has not been run**.
- It is **not** a live Vapi verification: no browser call, no `vapi:check` against the live dev assistant.
- The counts are counts over a hand-built scenario set, not statistics about any rate.

`test/services/evaluation/evidence_test.rb` fails if these files go stale relative to the code, or if a live item is ever
reported as a result instead of `PENDING`.
